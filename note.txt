1.stream=True的效果:
核心解答: response 是一个可迭代的流对象，可以不断从服务器取回新片段，可以把它想成水龙头，水一流出来，就能立刻接到

代码片段:
    response = client.chat.completions.create(
        ...,
        stream=True
    )

    for chunk in response:
        ...
    解析:
        (1).程序向大模型服务发出请求
        (2).服务开始生成回答
        (3).不必等完整回答生成完，create() 就会立刻返回 response 这个“流”
        (4).随后进入 for chunk in response
        (5).每当服务端生成了一小段新文本，循环就拿到一个 chunk
        (6).没有新文本到达时，循环会暂时等待；不是不停空转
        (7).服务端发送结束标志后，循环结束



2.所有python中的流对象都可以像这样遍历吗  -   需要实现可迭代协议

3.这种用for循环直接遍历流对象，来不断取出新来的元素的操作，在C++里面好像没有吧，并且想要实现这个循环应该也不简单，各种细节标志等都要我自己来控制      -       一般需要借助网络库提供的回调、阻塞读取，或 C++20 协程(来数据就调用这个协程)

4.stream=False时，这个response对象应该不是流对象了，直接时一个普通对象了？
| 参数 | `response` 的性质 | 取内容方式 |
|---|---|---|
| `stream=True` | 流式可迭代对象 | `for chunk in response` |
| `stream=False` | 完整响应对象 | `response.choices[0].message.content` |

12.st.session_state保存streamlt中的控件状态

    (2).没有写 key 的控件，Streamlit 会有内部标识来管理它，但你不应依赖某个 st.session_state.xxx 名称去读写它
        //NOTE - 如果没给一个控件设置key，Streamlit会根据组件类型、按钮文字、位置/参数等自动生成内部 ID，但是如果正好凑巧两个同层级、参数相同的按钮的key相同，streamlit会报错：StreamlitDuplicateElementId

    (3).一个控件在通过key和session_state的某个key绑定之后不可以：“在这个控件被创建出来之后再通过session_state api来改变这个控件的值“，原因：
    组件创建时，Streamlit 已经决定该输入框本轮要显示什么值；若后面再改变session_state api，相当于组件已经渲染到页面后，又在后端偷偷改它的绑定值前端可能显示旧值、后端却存新值，因此 Streamlit 直接禁止这种顺序
    (4).st.session_state不是普通的全局字典，它依赖 Streamlit 当前的运行上下文(和streamlit主线程绑定在一起了)，只有在streamlit主线程里访问st.session_state才知道是访问哪个线程(浏览器会话)的session_satte状态
    所以如果出现多线程异步任务，不要在非streamlit主线程中访问session_satte，可以把session_state信息通过参数的形式传递进去

17.st.write_stream(stream, *, cursor=None)
(1).函数核心参数:
核心只有一个参数stream，一个可迭代对象 / 生成器，它能不断产出要显示的数据

(2).函数效果:
不断向当前streamlit容器写对应数据，直到全部写完才返回

(3).函数返回值: list[Any] | str
是整个流全部输出完毕之后拼起来的完整结果

(4).该函数的阻塞性质
st.write_stream 会阻塞当前脚本后续代码：它会不断从传给它的 stream生成器 中取出 yield 的正文片段，每取得一段就立即渲染；直到生成器结束，才执行后面的思考过程渲染代码

18.python函数中中yield关键字
(1).效果
立刻交出一个值，并记住当前函数执行位置(函数还未结束)；下一次调用next()时从这一行后面继续执行
函数执行到yield之后控制流会走到函数外面，只是“暂停并交回控制权”；总共只有一个线程，不是创建新线程，也不是并行执行

(2).返回值
有 yield 的函数会变成生成器函数，其返回的对象是特殊的生成器对象
生成器函数的返回值生成器对象在被赋值是只是保存了一个对于该生成器对象的引用，还没有启动这个流/生成器
在流式输出语境下可以把它简单理解为一个能按需不断产出数据的“流对象”

(3).生成器对象
生成器对象实现了迭代器协议__next__()，在生成器对象语境下可以理解为通过next(<对象>)来获取下一个产物

(4).完整获取生成器对象产物的流程
脚本代码:
    def gen():
        yield 1
        yield 2
        return "结束信息"
    g = gen()
    try:
        while True:
            print(next(g))
    except StopIteration as e:
        print(e.value)  # 结束信息
    正常 for 循环只能拿到 1、2；执行到 return 时，生成器结束，return 后面的值不会作为普通元素产出，而是放进 StopIteration.value 并作为异常抛出
    return 的作用主要是提前结束生成器；多数情况下直接写 return 即可；yield 是暂停并产出值，return 是彻底结束

(5).嵌套流解析流程(以函数中包含yield关键字举例)
流生成器需要有人驱动，一般只有一个驱动语句调用next()驱动最外层的函数，对于每一层函数，被驱动时会从yield处继续向后执行代码，一般会在循环语句处取出下一个流对象，循环语句的迭代相当于对更深层的生成器函数调用next()，此时进入更深层的函数，最后一层函数(循环语句直接作用在真正的流上，没有更深层的函数，会直接取出对应的流，然后执行到最深层对应的yield，控制权开始逐层向上返回)
例如代码中: "模型返回的原始流 --> extract_content_stream --> parse_agent_response_stream" 就是一条嵌套流，获取正文时的流程应为:
st.write_stream()
  ↓ next(stream_gen)
parse_agent_response_stream()               #层1
  ↓ for content in content_stream
  ↓ next(content_stream)
extract_content_stream() #层2
  ↓ for chunk in stream_response
  ↓ 从 Ollama/OpenAI 流取一个 chunk           #"真正"的流
  ↓ 处理 reasoning，刷新思考框
  ↓ yield 正文 content                       #从层2返回层1
parse_agent_response_stream() 收到 content
  ↓ 解析 AGENT_META 或正文
  ↓ yield 正式回复片段                        #从层1返回main
st.write_stream() 收到正式回复片段并渲染

非渲染正文时的流过程:
    - 模型输出思考过程阶段:
    因为content字段大部分时候为空，所以大部分控制流都在extract_content_stream()函数内部的for循环内打转(一直continue，没有机会执行yield返回上层函数，但是这个过程会调用render_reasoning_chunk()函数，该函数内部会渲染思考站位块)
    - 模型输出元数据阶段(假设很长)
    因为一直没有读取到AGENT_META_CLOSE导致meta_end == -1，所以一直在parse_agent_response_stream()函数内部的for循环内打转(一直continue，没有机会执行yield返回上层函数) --> 进入extract_content_stream，因为此时content非空，所以可以yield content返回parse_agent_response_stream

| C++ | `std::ofstream(path)` | — | 自动创建 |

30.python中变量赋值终极含义
核心就一句话：变量名绑定对象，所有 "变量放在等号左边" 全部理解为 "在给一个名字绑定对象"
Python 变量名像可重新绑定对象的引用，放在等号左边就是“在改变引用指向”

a = [1, 2] #NOTE - 给a绑定[1,2]
b = a          #NOTE - 这里是给b绑定a对象；结果为a、b 指向同一个列表

b.append(3)     #NOTE - 因为b和a绑定的是同一个对象，所以这里为修改同一个对象
print(a)        # [1, 2, 3]

b = [4, 5]      #NOTE - 这里是给a重新绑定对象，所以不影响 a
print(a)        # [1, 2, 3]
print(b)        # [4, 5]

38.concurrent.future使用方式
概念：
    Python 标准库中的一个包，用于简化并发编程，模块提供线程池和进程池的高层次接口，一般ThreadPoolExecutor适合处理 I/O 密集型任务，ProcessPoolExecutor适合处理 CPU 密集型任务
使用：
    (1).先创建ThreadPoolExecutor/ProcessPoolExecutor对象，关键参数为max_workers
    (2).使用submit提交任务，关键位置参数为要执行的函数和函数参数
    (3).submit返回的对象为Future类，可使用done()判断是否完成，result()获取结果(future.result() 默认会阻塞当前线程，直到后台任务完成、失败或被取消；常见做法为先判断done，再调用result())
异常：
    发生异常时，submit()函数返回的 Future 会把后台线程中的异常保存起来
    此时future.done() 会返回 True，调用future.result() 才会重新抛出该异常
    所以在获取result的时候一般包在try catch块中
as_completed()函数：
    用途：给它一批 Future，谁先完成就先返回谁
    as_completed(futures) 返回迭代器；for 会阻塞等待，直到至少有一个任务完成
    例子：
    for future in as_completed(futures, timeout=5):
        ...
    阻塞等待一批future对象完成，完成一个for就拿到一个完成的Future对象，超过5s之后还没拿到下一个Future对象，就抛出TimeoutError
线程任务参数传递：
    在submit()中传递给线程任务函数的参数还是引用传递，不是值拷贝！！所以在线程函数里面修改这个变量在线程外面看得到修改
丢弃/取消任务：
    del future通常只是删掉页面保存的future引用；后台线程任务和 HTTP 请求仍会继续，模型仍会生成标题；只是完成后结果没人读取，相当于丢弃结果
    future.cancel()对已运行任务(不在线程池中，已经开始执行线程任务函数)通常返回 False，不会中断线程；只有任务还在线程池队列中、尚未开始执行时才会取消成功，后续不再调用线程任务函数

42.python的可变对象与不可变对象
    (1)区别: 在赋值后能不能原地修改对象本身
        Python的 = 都是让变量名指向某个对象(添加引用)，默认不会复制对象
        = 只是共享对象；可变对象的“修改”会影响所有引用，不可变对象的“修改”实际是创建新对象并重新绑定变量名
    如果想要像C++里面那样的拷贝，需要使用copy()成员函数:
        a = [1, 2, 3]
        b = a.copy()      # 推荐，语义最清楚
    并且还需要区分浅拷贝和深拷贝

    (2).不可变对象的成员方法特点:
    不可变对象不能原地修改；带有“修改”性质的成员方法通常是返回一个新对象，原对象不变
    例如:
    s = "hello"
    new_s = s.upper()
    print(s)      # hello
    print(new_s)  # HELLO
    str 的 upper()、replace()、strip() 等都是这样

43.python的copy模块
(1).使用
    # 导入copy库
    import copy

    copy.copy() # 浅拷贝
    copy.deepcopy() # 深拷贝
(2).相关事项:
    - 对于不可变对象，本来就不存在=通过赋值之后的名字引用修改原对象的可能，所以对于int, str这类对象通常直接返回原对象本身
      例如:
      import copy
      x = "hello"
      y = copy.deepcopy(x)
      
      print(x is y)  # 通常为 True
    - 可变对象递归复制
    - 对于可变不可变对象的嵌套情况，一句话:
      如果内层包含可变对象，那它的所有外层对象都需要进行拷贝(先检查内层，再决定外层)
    例如:
    import copy

    a = ([1, 2], "hello")
    b = copy.deepcopy(a)

    print(a is b)        # False，元组不是同一个(元组包含的第一个元素是list，为可变对象)
    print(a[0] is b[0])  # False，内部列表也不是同一个(list是可变对象)
    print(a[1] is b[1])  # True，字符串可复用(字符串是不可变对象)

    - memo 缓存
      memo 是本次复制过程中的“已复制对象记录表”，主要解决两个问题
      第一，避免循环引用无限递归，例如:
      import copy

      a = []
      a.append(a)       # 列表内部引用自己
      
      b = copy.deepcopy(a)
      print(b is b[0])  # True

      第二，保留原对象中的共享关系，例如:
      import copy

      child = [1, 2]
      a = [child, child]
      b = copy.deepcopy(a)
      
      print(b[0] is b[1])  # True
      print(b[0] is child) # False

    - 拷贝的另一种写法:
    假设a为list对象，此时: b = list(a)意识为
    根据 a 里的元素，创建一个新的 list 对象，然后赋给b

46.Base64
Base64 是一种“把二进制数据写成普通文本字符串”的编码方式
(1).在让模型处理图片类请求时，具体流程为:
    (1).先在本机将图片转换为Base64编码的字符串
    (2).在json请求中传递转换为字符串之后的图片: data:image/jpeg;base64,<图片对应的Base64字符串>
    (3).服务端拿到Base64字符串之后再解码还原出图片字节，交给模型处理

(2).典型应用
    - 网页内嵌小图标
      CSS、HTML 里可以直接写图片，不必额外请求一个 .png 文件
      <img src="data:image/png;base64,iVBORw0KGgo...">
      适合很小的图标；大图不适合
    - 接口上传图片、音频、PDF
      把图片转成 Base64，放入 JSON 请求体
      例如 OCR 接口、AI 图片识别、身份证识别、语音识别接口
    - 邮件附件
      传统邮件主要是文本格式，附件通常通过 MIME + Base64 编码放进邮件内容中，收件客户端再还原成图片、压缩包或 PDF
    - Token / 基础认证中的文本传递
      HTTP Basic Auth 常把 用户名:密码 转成 Base64：
      Authorization: Basic dXNlcjpwYXNz
      但这只是编码，不安全；必须配合 HTTPS，不能把它当加密
    一句话：Base64 是“把二进制塞进文本通道”的通用办法，但要付出约 33% 体积膨胀的代价

49.Pillow 图片处理
核心作用：Python 中读取、校验、缩放、裁剪、保存图片的常用库；当前聊天项目主要用于校验用户上传的图片真实格式

安装：
    python3 -m pip install Pillow

导入：
    from io import BytesIO
    from PIL import Image, UnidentifiedImageError

(1).打开图片并读取基本信息
    with Image.open("example.png") as image: # 打开失败抛出UnidentifiedImageError异常
        print(image.format)  # "PNG"，真实图片格式

    try:
        with Image.open(BytesIO(raw_bytes)) as image:
            image_format = image.format
            image.verify()
    except (UnidentifiedImageError, OSError):
        raise ValueError("不是可读取的图片")

    if image_format not in {"PNG", "JPEG", "WEBP"}:

    image.verify() 用于发现损坏的图片结构；调用后当前 image 对象不能继续使用，需要重新 Image.open()

(3).生成缩略图

    WRONG_POINT - thumbnail() 会直接修改原来的 Image 对象；原图之后还要使用时必须先 copy()

(4).固定尺寸缩放与裁剪
    with Image.open("origin.png") as image:
        resized = image.resize((512, 512), Image.Resampling.LANCZOS)
        resized.save("resized.png")

        # 坐标含义：(左, 上, 右, 下)，不是 (左, 上, 宽, 高)
        cropped = image.crop((100, 50, 500, 350))
        cropped.save("cropped.png")

    resize()：强制指定宽高，可能改变原图比例
    crop()：截取矩形区域，右 = 左 + 宽，下 = 上 + 高

(5).保存与格式转换
    with Image.open("origin.png") as image:
        image.convert("RGB").save("result.jpg", "JPEG", quality=90)

    save(路径)：通常根据文件后缀判断输出格式
    save(文件对象, format="PNG")：写入 BytesIO 等文件对象时必须明确填写 format
    PNG 可能是 RGBA（带透明通道），JPEG 不支持透明通道；保存 JPEG 前通常先 convert("RGB")

- thumbnail时按比例缩放，不超过对应长宽的最大限制，resize()时强行缩放，有拉伸副作用
- Image读取图像时是通过文件头，streamlit的chat_input只是通过文件后缀来限制传入的文件类型，所以不能信任streamlit前端传入的文件类型
- resize()常用插值算法:
算法	速度	画质特点	适合场景
NEAREST	最快	直接取最近像素，边缘锯齿明显	像素画、标签图、掩码图
BOX	快	缩小时做简单平均，质量一般	快速缩小、不在意细节
BILINEAR	中等	较平滑，但文字和边缘容易模糊	对速度有要求的普通预览
HAMMING	中等	比双线性更锐利，较少块状感	特定缩小场景，较少主动使用
BICUBIC	较慢	画质和速度平衡，Pillow 默认	大多数普通图片
LANCZOS	最慢	细节保留最好，缩小截图/文字通常效果好；极少数边缘可能有轻微光晕	高质量缩略图、截图缩小
- verify()校验图像是否损坏会推进底层文件读取位置，调用该函数后如果想要继续操作图片例如: 读取像素、缩放、保存等，需要重新Image.open()，失败抛出OSError

格式能不能转换，取决于目标格式能否表达当前图片的信息；必要时 Pillow 会先改变 mode，再按目标格式编码
常见格式与区别:
| 格式 | 特点 | 适合场景 | 不适合 |
|---|---|---|---|
| PNG | 无损、文字边缘清晰、支持透明 | 代码截图、报错截图、界面截图、图标 | 大照片，文件会较大 |
| JPEG | 有损压缩、文件小、不支持透明 | 手机照片、风景、人像 | 代码和小文字截图，边缘可能有模糊压缩痕迹 |
| WEBP | 可有损也可无损，可支持透明，通常体积较小 | 网页图片、需要兼顾体积与质量 | 某些旧软件兼容性较弱 |
| GIF | 调色板颜色有限，可做简单动画 | 简单动图 | 高清照片、代码截图 |
| BMP | 基本不压缩，文件很大 | 少见的兼容场景 | 日常传输和网页 |


(6).Image.format与Image.mode
    Image.mode：Pillow 内存中每个像素的颜色组成方式，图片解码后，像素在内存中以什么结构保存
        常见值：
            - RGB：红、绿、蓝三种颜色
            - RGBA：RGB + Alpha 透明度
            - L：灰度图
            - LA：灰度 + 透明度
            - P：调色板模式，像素存的是颜色表索引，常见于 GIF、部分 PNG
        mode 会影响能否保存为某种格式。例如 RGBA 不能直接保存为 JPEG，因为 JPEG 不支持透明度。
    Image.format：Pillow 从文件中识别出的文件编码格式
        常见值：
            - PNG
            - JPEG
            - WEBP
            - GIF
        它决定重新 save() 时该用什么编码规则：image.save(buffer, format=image.format)
    
    一个 .png 文件可能是 RGB，也可能是 RGBA、P 或 L；所以它们不是一一对应关系

        base64.b64encode(<readblebuffer(字节)>) -> bytes
        将原先二进制结果编码为base64字符串
        为什么返回bytes二不是str: base64 的本质仍是“二进制数据转二进制数据”：它把任意字节转换成只包含 ASCII 字符对应字节的结果；函数不擅自决定是否将二进制数据按照ascii编码为字符串，方便直接继续写文件、传网络协议等二进制场景
    (2).base64.b64encode(<readblebuffer | str (字符串/字节buffer)>) -> bytes
        将base64字符串解码为原先的二进制字节

54.dict.fromkeys()
字典的keys不能重复，重复会覆盖前面的旧值

dict.fromkeys() 用一批 key 快速创建字典，并给它们统一设置初始值
常见用途：给一组统计项、配置项或状态项做初始化
result = dict.fromkeys(["PASS", "FAIL", "ERROR"], 0)  # {'PASS': 0, 'FAIL': 0, 'ERROR': 0}

注意：如果初始值是可变对象（如 []、{}），所有 key 会共享同一个对象
data = dict.fromkeys(["a", "b"], [])
data["a"].append(1)
print(data)
# {'a': [1], 'b': [1]}  # b 也变了

这种情况建议用字典推导式：
data = {key: [] for key in ["a", "b"]} # key从["a", "b"]里面取，每个key的value为空列表

55.object类
object 是 Python 所有类的共同“最顶层父类”，Python 3 中，所有自定义类默认都继承 object
它带来的基础能力包括：
- __str__()：print(对象) 时如何显示
- __repr__()：调试时对象如何显示
- __eq__()：两个对象用 == 怎么比较
- __init__()：创建对象时初始化
- __class__：查看对象所属的类

当写在类型注解里，object 表示：这个参数可以接收任意 Python 对象，给类型检查工具和读代码的人看：函数不要求参数必须是 str、int、列表等某种具体类型
与 Any 的区别：
Any 相当于“别检查我”，object 相当于只能安全地使用所有对象都有的基础操作，例如下面:
def f1(value: object):
    value.upper()  # 类型检查通常会报错：object 不保证有 upper()

56.js.load/loads()返回值

- JSON 对象 {...} → dict

57.上下文与max_tokens
    token:
        token 可以理解为模型切分文本后的最小片段，不严格等于字或词中文场景大致可以粗略认为：一个汉字通常约占 1～2 个 token
    上下文窗口:
        模型一次最多能读入多少内容，包括系统提示词、历史对话、图片摘要等
    max_token:
        - 这次最多能输出多少内容，包括其思考内容，输出的正式回复；如果思考过程中使用了较多的token，在回复时就更容易达到max_tokens限制
        - 对 Ollama 而言，它对应的底层概念是 num_predict；官方当前文档中 num_predict 默认值是 -1，即不人为限制生成 token 数，模型会在自然结束、遇到停止词或上下文空间耗尽时停止
    为什么要限制max_tokens:
        模型偶尔可能陷入重复输出，单次请求持续很久
        代码当前还有 timeout=180.0，超过 180 秒客户端仍可能中断请求
        不能突破上下文窗口：输入提示词、历史记录、图片内容、已生成的思考和正文共同占用上下文剩余空间耗尽时，仍会被截断
        上下文越大，显存占用越高；Ollama 官方也说明增加上下文长度会提高内存需求

60.getattr()函数
    getattr() 用来动态地按字符串获取对象的属性或方法
    传给getattr() 的属性名可以来自变量、配置文件或用户选择
    常见用途：
        - 属性名运行时才确定，例如:
        class Tool:
            def build(self):
                print("开始编译")

            def flash(self):
                print("开始烧录")

        tool = Tool()
        command = "flash"
        
        func = getattr(tool, command, None)
        if func is not None:
            func()
        # 常用于命令分发、插件式功能(上面的command可以通过外部配置传进来)
        - 安全读取可选属性：第三个参数是默认值，属性不存在时不报错，普通.访问属性时如果不存在会报错AttributeError，例如:
        timeout = getattr(config, "timeout", 10)

61.st.empty()
st.empty()
	函数作用: 创建一个只容纳一个元素的占位区域，后续调用返回对象的方法可替换其中内容
	返回值:
		成功: 返回可继续调用 markdown()、write()、empty() 等方法的占位对象
	注意事项:
		每次 placeholder.markdown() 会替换上一份内容，不会自动追加文本
